What the client came with

Every new client was onboarded by hand. Someone created the account, sent the welcome email, set up the Slack channel, built the Notion workspace — manually, every time. When that person was sick, clients waited. When they were busy, things got missed.

02 /

The plan I drafted

  • Make the Stripe payment the single trigger for onboarding
  • Run every setup step in a fixed order: account, welcome email, Slack, Notion
  • Alert the team only if a step fails — otherwise nobody needs to touch it
03 /

The process, step by step

Now a single Stripe payment event triggers the entire sequence. Accounts provisioned, emails sent, Slack invited, workspace ready — in order, without anyone touching it. The client logs in before the team even knows they paid.

  1. Payment trigger

    A Stripe webhook starts the Make.com scenario the moment a payment succeeds.

  2. Provision the account

    The client's account is created automatically with the plan they paid for.

  3. Welcome email

    A branded welcome email goes out with login details and next steps.

  4. Slack and Notion

    A client Slack channel is created and invited, and a Notion workspace is duplicated from the onboarding template.

  5. Team notification

    The team is told the client is live — after it's already done.

04 /

The bottleneck

! bottleneckDuplicate payment events

Stripe can deliver the same event more than once, which risked creating duplicate accounts and channels for one client.

05 /

How I fixed it

✓ fix

I stored each processed Stripe event ID and stopped the scenario if it had already been handled, so every client is onboarded exactly once.
